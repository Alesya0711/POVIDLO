# Контекстный помощник

При `LLM_MODE=groq` сервер отправляет запросы в Groq к модели `openai/gpt-oss-120b`. Для вызова используется стандартный Python `urllib`, отдельный SDK не нужен. Режим `stub` работает без внешней модели и включается явно. Без ключа в режиме Groq чат сообщает о недоступности; автоматического перехода на stub нет.

Инструкции модели имеют версию `kapibank-groq-3`. Все формулировки для пользователя должны быть по-русски, с точными русскими названиями кнопок и тёплым, прямым тоном. Английские JSON-ключи, значения `targetField` и машинный формат чисел остаются без изменений.

## Настройка

Для единого Docker-контейнера скопируйте корневой шаблон `.env.runtime.example` в `.env.runtime` и заполните `GROQ_API_KEY`. Параметры модели и режима Groq уже указаны. Секрет передаётся серверу через `--env-file`; не помещайте его в `VITE_*`, исходники или сообщения чата.

Для отдельного локального сервера используйте `kapibank-backend/.env.example`: скопируйте его в `kapibank-backend/.env` и задайте там ключ. Python читает `.env` из рабочего каталога, поэтому запускайте команды из `kapibank-backend/`. Корневой `.env.runtime` локальный Python-процесс не читает. Для режима без модели задайте `LLM_MODE=stub`.

Ручной запрос к настоящей модели запускается так, после настройки ключа в backend `.env`:

```sh
cd kapibank-backend
python ../development/tools/check_groq.py --case amount
```

Доступ к Groq зависит от ключа и лимитов аккаунта. Без живого запроса нельзя подтвердить доступ к модели или качество её ответов. Скрипт отправляет только синтетические примеры и не входит в единый runtime-образ.

## Экраны

Помощник доступен на главной странице, в опросе, каталоге, результатах подбора, продукте с калькулятором, личном кабинете, профиле, оформлении и карточке заявки, сводке условий. В разделах входа и работы сотрудника чата нет.

В оформлении передаются публичные условия продукта, сумма, срок, цель и только показанный результат предварительной проверки. В профиле помощник объясняет поля без передачи значений профиля. Карточка передаёт статус и отдельно условия предложения; сводка сообщает, доступно ли учебное подписание и завершено ли оно. Результаты подбора содержат причины отсутствия вариантов, каталог и подбор различают загрузку, ошибку и полученный список.

## Предложения и границы

Предложение может изменить только одно поле за раз:

| Экран и поле | Допустимое предложение |
| --- | --- |
| `questionnaire` / `principal` | Сумма |
| `questionnaire` / `termMonths` | Срок |
| `questionnaire` / `industryDescription`, если `answers.industry=other` | Описание другой сферы |
| `product` / `financing_terms` | Сумма или срок |
| Остальные случаи | Только объяснение, `proposal=null` |

Правовую форму, возраст бизнеса, категорию сферы и цель выбирает сам пользователь. Описание другой сферы можно предложить только после выбора категории `other`.

Сумма должна быть положительной строкой с двумя знаками после точки и не более чем 12 цифрами до неё, например `1500000.00`. Срок - целое число от 1 до 600. Описание сферы - непустая строка до 200 символов. Пояснение к предложению - непустая строка до 500 символов. Ограничения продукта и обычная проверка формы сохраняются. Применённое значение не означает, что кредит доступен.

Передавайте модели только данные текущего экрана, необходимые для ответа: например, условия видимых продуктов и предварительные расчёты. Контекст не является подтверждённой банковской записью. Не добавляйте туда пароли, токены, реквизиты счетов, email, внутренние заметки или полный профиль компании. Свободный текст пользователя не проходит DLP-фильтрацию; человек может самостоятельно написать чувствительные сведения.

Функция `clean_context` пропускает только разрешённые ключи, ограничивает списки 20 элементами, глубину - пятью уровнями, строки - 2000 символами и весь JSON-контекст - 12000 символами. История модели содержит до 10 последних сообщений с ролями `user` и `assistant`, суммарно до 4000 символов. Передаются целые сообщения с конца истории; более ранние сообщения отбрасываются, чтобы ограничить размер запроса. Потоковой выдачи, function calling и RAG нет. Модель не рассчитывает платёж и не принимает кредитное решение.

## Вызов Groq и ошибки

Endpoint: `https://api.groq.com/openai/v1/chat/completions`. Используется Structured Outputs с `response_format.type=json_schema` и `strict=true`, схема содержит только поля, доступные на текущем экране. Запрос задаёт `temperature=0.2`, `reasoning_effort=low`, `include_reasoning=false` и `stream=false`. Значение `max_completion_tokens` по умолчанию - 2048; `reasoning_format` для этой модели не передаётся.

Ответ дополнительно проверяется сервером: требуется завершённый ответ с `finish_reason=stop` и JSON только с `reply` и `proposal`. Текст ответа не может быть пустым или длиннее 5000 символов; тело HTTP ограничено 200000 байтами. Markdown-обёртки, неверные типы, неподдерживаемые поля, обрезанные ответы и недопустимые значения не применяются.

Интерфейс показывает понятное сообщение о недоступности или достижении лимита, сохраняет введённый вопрос и позволяет начать новую беседу после истечения старой. Нет ключа или модели, истёк тайм-аут, провайдер отказал в доступе, достигнут лимит, произошёл сетевой сбой или пришёл некорректный ответ - API возвращает `503 ASSISTANT_UNAVAILABLE`. Для ответа Groq с кодом 429 сообщение указывает на лимит запросов. Автоматических повторов и fallback нет. Текст ошибки провайдера, ключ и запрос не отправляются клиенту. При ошибке вопрос остаётся в интерфейсе, а поле не меняется. Доступность чата зависит от ключа, лимитов аккаунта и внешней сети; основной путь работы с заявками не зависит от модели.

## HTTP-контракт и подтверждение

`POST /api/v1/assistant/messages` принимает сообщение и контекст экрана. Пример:

```json
{
  "clientMessageId": "unique-message-uuid",
  "message": "Нужно полтора миллиона",
  "context": {
    "screen": "questionnaire",
    "field": "principal",
    "data": {"answers": {"principal": "1000000.00"}}
  }
}
```

Ответ содержит `conversationId`, `reply`, `dataMode` (`groq` или `stub`) и `proposal` либо `null`. Следующие сообщения беседы передают `conversationId`. ID и revision предложения назначает сервер.

Для подтверждения клиент вызывает `POST /api/v1/assistant/proposals/{proposalId}/confirm` с `revision` и актуальным контекстом. Сервер проверяет владельца, срок действия и хеш очищенного контекста. Изменившийся контекст даёт `409 STALE_PROPOSAL`; чужое или истёкшее предложение - `404`. После успеха интерфейс применяет возвращённое `targetField` и `confirmedValue` к редактируемой форме или калькулятору.

Открытый чат обновляет контекст, если данные соответствующего экрана изменились. Перед применением клиент дополнительно проверяет, что экран, его данные и пользователь остались прежними. Подтверждение меняет только значение поля в текущем интерфейсе. Оно не редактирует заявку в серверной базе, не запускает банковское действие, не выдаёт кредит, не переводит деньги и не создаёт юридически значимую подпись. Все банковские операции приложения учебные и моделируются.

Авторизованная беседа связана с пользователем, гостевая - со случайной HttpOnly cookie. Беседа действует сутки; это срок доступа, а не фоновое удаление строк. PostgreSQL сохраняет до 20 записей истории в беседе. `clientMessageId` защищает от повторной отправки в сохранённой истории этой беседы, а не глобально.

## Ручная проверка модели

Скрипт `development/tools/check_groq.py` поддерживает случаи `amount`, `term`, `calculator`, `ambiguous`, `missing-data`, `injection` и `industry`. Запускайте по одному запросу из `kapibank-backend/`, учитывая лимиты Groq:

```sh
python ../development/tools/check_groq.py --case term
python ../development/tools/check_groq.py --case calculator
python ../development/tools/check_groq.py --case ambiguous
python ../development/tools/check_groq.py --case missing-data
python ../development/tools/check_groq.py --case injection
python ../development/tools/check_groq.py --case industry
```

Скрипт проверяет ожидаемое предложение, но не оценивает точность русского текста. Ответ нужно просмотреть вручную на соответствие фактам и сценарию. Без ключа и живого вызова результаты модели не проверены.
